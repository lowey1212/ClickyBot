ClickyBot 0.1.62 runs fixed-interval backup 1 rules during Aion combat. Previously combat mode bypassed the normal rule list, so an existing "press 1 as a back up" rule never executed regardless of its cooldown.

Use an enabled Always / KeyPress / 1 / WhileTrue rule with no AND gate and random reaction disabled. A cooldown of 5000 ms sends a backup 1 about every five seconds, starting five seconds after combat starts. The rule retains its selected keyboard input mode. A minimum five-second backup interval prevents older 100 ms rules from turning into rapid-fire input; the normal combat sequence is unchanged. Backup scheduling runs before HUD detection, so capture errors, range-message capture failures and uncertain cooldown OCR do not block the periodic tap. A failed backup action retries at its interval while combat continues. Focus loss pauses input; focus restoration sends at most one overdue tap, without a catch-up burst. Stop/F7 cancels combat and its backups together. This does not restart a stopped or crashed application, and timing follows combat polling/recovery delays rather than a hard real-time guarantee.

Validation: simulated production driver reports and deterministic scheduling during held combat, persistent capture/range errors and uncertain OCR; delayed first tap, five-second repeats, disabled and gated rules, driver failure retries, focus pause/resume without a burst, and manual Stop cleanup. Existing gathering, image, driver input, combat, WPF editor/updater and inspector checks pass without game input. Installer and portable package versions and contents verified.
